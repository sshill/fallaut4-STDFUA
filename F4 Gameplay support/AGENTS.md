## 1. Протокол узгодження: Саммарі діагностики ➔ Саммарі змін ➔ Єдине підтвердження
Коли користувач повідомляє про проблему, баг або ставить нове завдання під час гри, агент діє за чітким протоколом:

### Етап 1: Саммарі діагностики (Diagnosis Summary)
- Що саме сталося, які симптоми та точна причина збою.
- Результати перевірки логів та системного стану (читання логів `game_crash.log`, `Papyrus.0.log` та конфігів `Fallout4Prefs.ini` строго через `view_file` без написання ad-hoc скриптів).
- Короткі, чіткі висновки без зайвої води.

### Етап 2: Саммарі пакета змін (Package Summary)
- Чітка таблиця усіх файлів, які будуть змінені або створені.
- Список конкретних дій та налаштувань.
- Очікуваний результат після застосування пакета.
- Запит **ОДНОГО** загального підтвердження від користувача на весь пакет.

---

## 2. Пакетне виконання без клікання на кожній команді (Batch Execution)
- **Ніяких покрокових запитів**: Користувач не повинен підтверджувати кожну команду окремо.
- Після схвалення пакета змін агент:
  1. Використовує внутрішній інструмент `replace_file_content` для редагування `.ini` чи текстових файлів конфігурації.
  2. Системні команди хоста з `BypassSandbox: true` виконуються пакетно в межах затвердженого плану.
  3. Одразу після виконання надає фінальний короткий звіт про результат (Walkthrough) та готовність до перевірки в грі.

## 4. Обов'язкова процедура інспекції екрана гри через Git
- Заборонено прямий запуск X11-утиліт у пісочниці.
- Використовувати виключно стандартизований скрипт стенда:  
  `bash /home/hills/Documents/fallaut/capture_screen_to_git.sh "<контекст>"`  
  *(Скрипт автоматично виконує збереження, валідацію, точковий `git add -f screens/latest.png` та локальний коміт).*
- Перегляд кадру — строго через нативний `view_file` (`screens/latest.png`).
- Для консольної перевірки стану квестів у вікні гри агент оновлює [`game/copilot_cmd.txt`](file:///home/hills/Documents/fallaut/game/copilot_cmd.txt) для запуску через `bat copilot_cmd`.
