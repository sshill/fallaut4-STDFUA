# 🕹️ Аудит: Проблема подвійних драйверів та калібрування аналогових стіків DS4 + FootSwitch

## 1. Контекст та симптоми інциденту
У ході ігрової сесії під керуванням Linux Wine 10 було зафіксовано два пов'язаних дефекти керування:
1. **Маніпулятори не спрацьовують з першого разу:**
   - Перші натискання кнопок або відхилення стіків ігнорувалися рушієм Fallout 4.
2. **Аномальна кінематика стіків (затримка + неконтрольований розгін):**
   - На початку руху стіка відчувалася помітна затримка (deadzone lag), після подолання якої кут огляду або рух персонажа раптово зривався в гіперчутливе прискорення.

---

## 2. Аналіз першопричин (Root Cause Analysis)

### А. Проблема «2х драйверів» (Double Input Collision)
* **Архітектура колізії:**
  - **Драйвер 1 (Фізичний бекенд Wine):** Підсистема `winebus.sys` / DirectInput / SDL напряму сканує шину ядра Linux та намагається відкрити дескриптори фізичного контролера Sony DualShock 4 (`054c:09cc`, `/dev/hidraw*`, `/dev/input/js0`, `event7`) і педального блоку FootSwitch (`3553:b001`, `event10/11/20`).
  - **Драйвер 2 (Віртуальний XInput емулятор):** Демон `footpad_mapper.py` створює через `/dev/uinput` віртуальний геймпад `Microsoft X-Box 360 pad` (`045e:028e`), транслюючи об'єднаний потік подій від геймпада та педалей.
* **Механізм збою:**
  - Рушій Fallout 4 (Creation Engine) реєстрував **одночасно два контролери** (слот 0 і слот 1) або колідував між DirectInput та XInput.
  - При русі або натисканні віртуальний пристрій транслював активну подію, а фізичний DirectInput бекенд Wine у той же квант часу транслював нульове положення осі. Виникав стан гонитви (race condition), внаслідок якого перша дія відкидалася рушієм.
  - Додатково: при неналежному захопленні вузлів педалей FootSwitch клавіатурні сканкоди (`Shift`, `q`, `f`) потрапляли в X11, перемикаючи Fallout 4 у режим клавіатури і тимчасово блокуючи ввід з геймпада.

### Б. Причина затримки та неконтрольованої роботи стіків (Коміт `060e6e1`)
Експериментальна крива `scale_stick()` із коміту `060e6e1` містила несумісні параметри:
1. **Занадто широка мертва зона (120..136):** рух стіка біля центру повністю ігнорувався («затримка»).
2. **Ступінчастий стрибок зсуву (+4500 / 13.7%):** при перетині порогу 136 сигнал миттєво стрибав до 4500 замість плавного наростання від 1.
3. **Гамма-крива 1.35 та передчасне насичення (248):** крута експонента призводила до раптового ривка та досягнення максимальних 32767 задовго до фізичного упору стіка («неконтрольована робота»).

## 3. Комплексне рішення (Architecture Solution)

### Рівень 1: Монопольне захоплення пристроїв (`EVIOCGRAB`)
У `footpad_mapper.py` реалізовано захоплення дескрипторів ядра через `ioctl(fd, EVIOCGRAB, 1)`:
* Фізичний геймпад DS4: `/dev/input/event7`
* Датчики руху DS4: `/dev/input/event8`
* Тачпад DS4: `/dev/input/event9`
* Педальний блок FootSwitch (Keyboard, Mouse, Aux): `/dev/input/event10`, `event11`, `event20`

### Рівень 2: Ізоляція на рівні udev та Wine
* `/etc/udev/rules.d/99-game-hardware-isolation.rules`: встановлено `MODE="0600", TAG-="uaccess"` для `054c:09cc` та `3553:b001`.
* `prefix/system.reg`: у секції `[System\ControlSet001\Services\winebus]` встановлено `"DisableHidraw"=dword:00000001` та `"DisableInput"=dword:00000001`.
* `launch_fallout4.sh`: експорт `SDL_GAMECONTROLLER_IGNORE_DEVICES` та `SDL_JOYSTICK_IGNORE_DEVICES`.

### Рівень 3: Відновлення плавної лінійної кривої стіків
Функцію `scale_stick()` у `footpad_mapper.py` повернуто до класичного лінійного профілю:
```python
    def scale_stick(self, val):
        # DS4 hardware reports 0..255. Hardware center fluctuates around 128..132.
        # Deadzone: 122..134 -> 0 (prevents jitter, phantom menu scrolling & drift in Pip-Boy)
        if 122 <= val <= 134:
            return 0
        elif val > 134:
            # Map 135..255 smoothly to 1..32767
            return min(32767, int((val - 134) * (32767.0 / (255.0 - 134.0))))
        else:
            # Map 121..0 smoothly to -1..-32768
            return max(-32768, int((val - 122) * (32768.0 / 122.0)))
```
* Мертва зона звужена до `122..134 -> 0` (повний захист від дрейфу в Піп-Бої).
* 100% лінійний, плавний відгук без затримок та ривків.

## 4. Результати верифікації
* **Геймпад:** відгук миттєвий, дрейф відсутній, спрацьовування з першого натискання.
* **Педальний блок FootSwitch:** підключено та захоплено (`event10/11/20`), перемикання гри на клавіатуру усунуто.
* **Статус стенда:** 🟢 **ШТАТНИЙ (PASS)**.
