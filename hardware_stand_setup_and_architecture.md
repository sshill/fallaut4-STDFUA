## 2. Еволюція платформи: Чому PS4 + Chiaki поступилися PC Linux

Початкова конфігурація стенда будувалася на базі консолі **Sony PlayStation 4** та клієнта віддаленої гри **Chiaki** через локальну мережу (IP: `192.168.0.106`, обліковий запис `sshill-sfua`). Практичні випробування виявили нездоланні архітектурні бар'єри закритої екосистеми Sony.

### Порівняльна матриця платформ

| Критерій оцінки | Sony PS4 + Chiaki (Remote Play) | PC Linux (Debian 13 + Proton) | Вплив на дослідження |
| :--- | :--- | :--- | :--- |
| **Доступ до консолі рушія (`~`)** | **Повністю заблоковано** Sony OS | **Повний нативний доступ** через тильду або F4SE пайпи | **Критично:** На PS4 неможливо виправити баг квесту; на PC баг усувається за 3 сек (`setstage`). |
| **Журнал подій рушія (Engine Logs)** | **Відсутній** («чорна скринька») | **Прямий потік у реальному часі** (`Papyrus.0.log`) | **Критично:** На PC подія бою чи травми пишеться в лог з точністю до мілісекунди. |
| **Стабільність зв'язку** | Помилка **`0x80108b10`** (*Remote is already in use*) при сні або розриві Wi-Fi | **100% автономність**, нульова залежність від роутера та мережі | На PS4 вимагало фізичного підходу й перезавантаження консолі кнопкою живлення. |
| **Контролер DualShock 4** | Chiaki блокував сенсорний тачпад через права udev (`/dev/input/event`) | **Повна підтримка** стіків, курків, тачпада, гіроскопа через `evdev` (250 Гц) | На PC тачпад працює нативно (виклик Pip-Boy / камера), фіксується мікротремор прицілювання. |

**Висновок тестування:** Закритість PlayStation 4 блокує побудову наукового зворотного зв'язку (Closed-Loop Biofeedback). Єдиним життєздатним рішенням для стенда є **відкрита операційна система Linux**.

### Виправлення відеодрайвера Mesa на Linux (Debian 12/13)
* **Діагностована проблема:** У стабільному репозиторії Debian версія драйвера `mesa-vulkan-drivers (22.3.6)` не містила ідентифікатора PCI ID `0xa7ad` свіжого процесора Intel Core 3 100U. Як наслідок, система видавала попередження `Driver does not support the 0xa7ad PCI ID` і скидала рендеринг у програмний емулятор CPU `llvmpipe`, де гра видавала лише 3–5 FPS.
* **Інженерне рішення:** Підключення репозиторію `bookworm-backports` та оновлення драйверів:
  ```bash
  sudo apt-get install -t bookworm-backports mesa-vulkan-drivers libgl1-mesa-dri intel-media-va-driver
  ```
  Це активує повноцінний апаратний драйвер **Intel ANV (Vulkan 1.3 / DXVK)** та апаратну трансляцію DirectX 11 $\rightarrow$ Vulkan.

> [!NOTE]
> **Хмарний vs Локальний ШІ:** Важкі нейромережеві моделі аналізу (Google Gemini) виконуються на серверах Google через API, тому ноутбук взагалі не витрачає гігабайти пам'яті та ресурси GPU на генерацію відповідей.

### Б. Асиметричний розподіл процесорних ядер
* **P-ядра (Performance, до 4.7 ГГц):** Повністю віддаються процесу `Fallout4.exe`. Вони забезпечують безперебійний прорахунок фізики Havok, штучного інтелекту NPC та рендерингу Creation Engine.
* **E-ядра (Efficient):** Обслуговують Gamescope, Bluetooth-стек гарнітури, збір R-R інтервалів Polar H10 та HTTP-запити до смартфона. Навантаження на E-ядра від хабу телеметрії становить лише **3–5%**, що унеможливлює просідання FPS у грі.

### В. Стек запуску гри (Gamescope + FSR Upscaling)
Для запобігання перегріву інтегрованого відеоядра гра запускається через мікрокомпозитор Valve `gamescope`:
```bash
gamescope -W 1920 -H 1080 -w 1280 -h 720 -U -F fsr -- %command%
```
* Гра рендериться внутрішньо в **720p (1280x720)** — це знижує навантаження на кристал iGPU в 2.2 рази.
* Апаратний просторовий апскейлер **AMD FidelityFX Super Resolution (FSR)** розгортає картинку до кришталево чіткого **1080p (1920x1080)** на великому екрані.
* **Результат:** Стабільні **55–60 FPS**, тиха робота кулерів, температура CPU/iGPU не перевищує 68°C.

### Деталізація кардіофазного трекінгу (Нейрокардіологія)
Polar H10 апаратно передає значення кожного R-R інтервалу в одиницях $1/1024$ секунди ($\approx 0.976$ мс). Це дозволяє не просто рахувати усереднений пульс, а визначати **точну фазу серцевого циклу в момент ігрової події**:
1. **Систола (0 – 350 мс від R-піку):** Скорочення шлуночків серця, стрибок тиску, активація барорецепторів дуги аорти. Відбувається природне гальмування кори головного мозку (Baroreceptor Gating).
2. **Діастола (350 мс – наступний R-пік):** Розслаблення шлуночків, тиск мінімальний. Мозок перебуває у фазі максимальної сенсорної чутливості та найшвидшої реакції.
*ШІ-система стенда порівнює, в яку саме фазу (систолу чи діастолу) гравець помічає загрозу, отримує поранення або робить постріл.*

## 7. Графічне прискорення браузера та зовнішня картографія (тези з b2bce7c5)

Під час дослідження та зачисток гравець використовує інтерактивну картографію `fallout4map.com` (MapGenie на базі рушія **MapLibre GL JS**).

### А. Розблокування WebGL та апаратного прискорення в Chrome
Через консервативний чорний список відеодрайверів у Linux (GPU blocklist), Google Chrome за замовчуванням вимикає апаратне прискорення для свіжих чіпів Raptor Lake-U, що призводило до білого екрана або зависання карти.
* **Налаштування через `chrome://flags`:**
  1. `Override software rendering list` $\rightarrow$ **Enabled** (обхід блоклиста драйверів).
  2. `Accelerated 2D canvas` $\rightarrow$ **Enabled**.
* **Команда термінального запуску з портом дистанційного керування для ШІ-агента:**
  ```bash
  google-chrome --ignore-gpu-blocklist --enable-gpu-rasterization --remote-debugging-port=9222 https://fallout4map.com/ &
  ```
* **Перевірка стану через `chrome://gpu`:**
  * `Canvas: Hardware accelerated`
  * `Compositing: Hardware accelerated`
  * `OpenGL: Enabled`
  * `WebGL / WebGL2: Hardware accelerated`

### Б. Різниця взаємодії: Людина проти ШІ-агента
* **Для очей людини (гравця):** Апаратний WebGL обов'язковий — він малює інтерактивне 3D/2D полотно `<canvas>`, тайли місцевості та 800+ векторних маркерів на частоті 60 кадрів/с.
